# Настройка и использование

Инструмент работает на Windows и Linux. Виртуальное окружение не требуется: библиотеки автоматически скачиваются в `.deps`, отдельно для каждой системы и версии Python. При первом запуске нужен интернет; библиотека определения языка занимает около 170 МБ.

## 1. Установка

Нужны [Git](https://git-scm.com/downloads) и [Python 3.10 или новее](https://www.python.org/downloads/) с `pip` — установщиком библиотек. На Windows включите `Add Python to PATH` («добавить Python в системный путь»). На Linux установите `python3` и `python3-pip` средствами своего дистрибутива.

Откройте терминал в корне репозитория игры, рядом с папкой `Resources`. Замените адрес ниже настоящим адресом опубликованного инструмента:

```text
git submodule add <АДРЕС_РЕПОЗИТОРИЯ_ИНСТРУМЕНТА> Tools/ss14-ai-auto-translate-tool
git submodule update --init --recursive
cd Tools/ss14-ai-auto-translate-tool
```

Если сабмодуль уже подключён в скачанном проекте, достаточно `git submodule update --init --recursive` из корня игры.

Проверьте Python и `pip`:

```text
# Windows
python --version
python -m pip --version

# Linux
python3 --version
python3 -m pip --version
```

На Windows готовые сценарии также умеют запускать Python через `py -3`.

## 2. Файл настроек

Из папки инструмента скопируйте шаблон:

```text
# Windows, PowerShell
Copy-Item .env.example .env

# Linux
cp .env.example .env
```

Откройте `.env` обычным текстовым редактором. Он читается автоматически и исключён из Git. Не публикуйте файл с секретными ключами. Настройки процесса имеют приоритет над `.env`; параметры запуска имеют приоритет над настройками файла.

## 3. Откуда берётся ИИ

Сам инструмент модель не содержит. Нужен внешний API (интерфейс доступа к сервису) или совместимый локальный сервер.

### Сторонний API

Получите у поставщика адрес, название модели и ключ. Запишите их в `.env`:

```dotenv
TRANSLATE_AI_BASE_URL=https://адрес-сервиса.example/v1
TRANSLATE_AI_MODEL=название-модели
TRANSLATE_AI_KEYS=секретный-ключ
TRANSLATE_AI_MAX_OUTPUT_TOKENS=8192
```

Адрес должен предоставлять совместимый с OpenAI путь `/chat/completions`. Обычный веб-чат без API не подходит. Несколько адресов, моделей и ключей можно перечислить через запятую.

### Локальный ChatMock

Следуйте [инструкции ChatMock](https://github.com/RayBytes/ChatMock). После установки войдите в аккаунт и запустите сервер:

```text
chatmock login
chatmock serve
```

Не закрывайте окно сервера во время перевода. Шаблон настроен на `http://127.0.0.1:8000/v1`; для локального адреса ключ не обязателен. В `TRANSLATE_AI_MODEL` укажите модель, доступную на вашем сервере.

## 4. Пробный запуск

Пробный запуск не обращается к ИИ и не изменяет локализацию. Он показывает план создания, перемещения и изменения файлов, ключи для перевода и размеры блоков. Недостающие библиотеки при первом запуске всё равно могут скачиваться в `.deps`.

```text
# Windows
.\scripts\windows\translate-all-ru.cmd -DryRun

# Linux
bash ./scripts/linux/translate-all-ru.sh --dry-run
```

Новые целевые файлы учитываются в памяти: они тоже присутствуют в плане. Если указан файл отчёта, в пробном режиме отчёт выводится в терминал, а не записывается.

## 5. Перевод

```text
# Windows: английский → русский
.\scripts\windows\translate-all-ru.cmd

# Linux: английский → русский
bash ./scripts/linux/translate-all-ru.sh
```

Для обратного направления используйте `translate-all-en.cmd` или `translate-all-en.sh` из соответствующей папки.

Подготовка восстанавливает зеркальные пути и порядок исходных ключей, сохраняя существующие переводы. Недостающие значения и атрибуты берутся из исходной локали. Ключи, существующие только в целевой локали, не удаляются молча. Разные переводы одного ключа в нескольких файлах вызывают ошибку: сначала разрешите конфликт вручную.

Затем ИИ получает обычные FTL-блоки, без JSON-обёртки. Ответ проверяется настоящим парсером Fluent, проверками служебной структуры и языка. Ошибка проверки передаётся модели при повторной попытке. Обрезанный ответ не записывается: блок уменьшается.

После завершения обязательно просмотрите изменения в игровом репозитории:

```text
git diff -- Resources/Locale
```

ИИ может ошибиться в терминологии или контексте. Проверки синтаксиса не заменяют чтение переводов человеком.

## Другие языки и папки

В `.env` измените `TRANSLATE_SOURCE_CULTURE` и `TRANSLATE_TARGET_CULTURE`, например `en-US` и `fr-FR`. Запустите общий сценарий, который использует эти настройки:

```text
# Windows
.\scripts\windows\translate.cmd --dry-run

# Linux
bash ./scripts/linux/translate.sh --dry-run
```

Для целевой локали используется `prompts/<код-локали>.md`. Если такого файла нет, работает универсальная подсказка `prompts/default.md` с подстановкой языков. Предпочтительно создать собственную подсказку на целевом языке. Свой словарь терминов задаётся через `TRANSLATE_GLOSSARY` или `--glossary`.

Пути к подсказкам, словарю, pass-листу и языковому профилю считаются относительно папки инструмента, а не текущей папки терминала. Можно указать абсолютный путь. `TRANSLATE_SOURCE_ROOT` и `TRANSLATE_TARGET_ROOT` задают папки локализации относительно корня игры.

Корень игры находится автоматически по `Resources/Locale`. При отдельной установке передайте `--repo-root` или задайте `SS14_REPO_ROOT`. Пример прямого запуска:

```text
# Windows
python run.py --repo-root C:/путь/к/игре translate-all --target-culture fr-FR --dry-run

# Linux
python3 run.py --repo-root /путь/к/игре translate-all --target-culture fr-FR --dry-run
```

Другой файл окружения выбирается параметром `--env-file /путь/к/настройкам.env`.

## Pass-лист и размер ответа

Названия, которые должны оставаться на исходном языке, перечислены в [pass_list.yml](pass_list.yml). Они исключаются из проверки языка, но английское описание рядом с разрешённым названием всё равно требует перевода.

Обязательно укажите реальное окно модели в `TRANSLATE_AI_MAX_OUTPUT_TOKENS`. По умолчанию используются тройной запас на расширение перевода и только 65% окна. Подробности расчёта, другие языки, пользовательские профили и повторы ошибок описаны в [CONFIGURATION.md](CONFIGURATION.md).

## Автоматический запуск в GitHub

Готовый [шаблон](examples/github-actions/auto-translate.yml) устанавливается отдельно в основной репозиторий игры. Он запускает перевод по расписанию и создаёт черновой запрос на слияние. Пошаговая настройка ключей и разрешений — в [GITHUB_ACTIONS.md](GITHUB_ACTIONS.md).

## Дополнительные команды

На Windows используйте `python`, на Linux — `python3`:

```text
python run.py repo-root
python run.py sync-strings --dry-run
python run.py validate --fail-on-errors
python run.py normalize --dry-run
python run.py --help
python -B -m unittest discover -s tests -v
```

Для обновления сабмодуля из корня игры: `git submodule update --remote --merge Tools/ss14-ai-auto-translate-tool`. Если после обновления возникла ошибка зависимости, удалите папку `.deps` и запустите инструмент снова.
